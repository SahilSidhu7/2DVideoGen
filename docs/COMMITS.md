# Commit messages

This is the style the history already follows, written down so new commits
keep to it. `tools/commitlint.py` checks it; the hook in `.githooks/` runs
that check on every commit for anyone who opts in.

## The shape

```
Correct README figures that mixed three checkpoints

The results table quoted 530 s (v1), 86.0% in-distribution (v2) and 75.0%
out-of-distribution (v3 sampled) as if they described one model. They are
now all v3-staged, the shipped checkpoint: 548 s training, 85.7% / 70.8%
under beam search, 75.0% out-of-distribution under sampling.

Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
Claude-Session: https://claude.ai/code/session_015YcuJr52s25qK33ur1tYRT
```

(`3fd7611`, body shortened to its first paragraph.)

## Rules

1. **Subject.** Imperative mood ("Add", "Correct", "Ignore", not "Added" or
   "Adds"), first word capitalized, no trailing period. 72 characters at
   most; 60 or fewer is better.
2. **Optional prefix.** Either a lowercase area followed by a lowercase
   verb (`paper: add SCALING.md, parameters vs data across the project`),
   or `Attempt N:` for commits that log an attempt (`Attempt 24: capacity
   is not the bottleneck; close the project`). Areas in use or expected:
   `paper:`, `model:`, `critic:`, `webapp:`, `render:`. There are no
   `feat:`/`fix:` types.
3. **Line 2 is blank.**
4. **Body.** Wrapped at 72 columns. Say why the change was made and what
   it means, not a list of what the diff already shows. A correction says
   what was wrong ("Post 2 implied the measurement work was mine ... It
   was not"). A one-line subject with no body is fine for trivial changes.
5. **Trailers last**, one `Key: value` per line, after a blank line:
   `Co-Authored-By:`, `Claude-Session:`, `Nightshift-Task:`,
   `Nightshift-Ref:`. Trailer lines and lines holding a URL may run past
   72 columns.

## What the linter enforces

| rule | level |
|---|---|
| empty subject, or nothing after the prefix | error |
| subject over 72 characters | error |
| subject ends with `.` | error |
| subject starts lowercase without an area prefix | error |
| line 2 not blank | error |
| subject over 60 characters | warning |
| body line over 72 columns (not a trailer or URL) | warning |

Errors stop the commit; warnings are printed and let it through. Merge,
revert, `fixup!`, `squash!` and `amend!` messages are generated by git and
skipped. Comment lines and anything below the `git commit -v` scissors
line are ignored.

Mood is not checked, because no small rule tells "Add" from "Adds"
reliably. That one is up to the writer.

## Opting in

```bash
git config core.hooksPath .githooks       # run the linter on every commit
git config commit.template .gitmessage    # start each message from the skeleton
```

Neither is set for you. To check a branch before pushing, or in CI:

```bash
python3 tools/commitlint.py --range origin/master..HEAD
python3 tools/commitlint.py --range origin/master..HEAD --quiet   # errors only
```
