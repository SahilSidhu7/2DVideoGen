# MODELS.md - the scene-script writers, versioned

Every model this project has trained to write a scene script, preserved so a
later attempt cannot silently overwrite an earlier one. **Nothing in Attempt 23
or later writes into `model/checkpoints/`.** New runs go to a new directory.

Load any of them with:

```bash
USE_TF=0 python model/scene_infer.py "<prompt>" --ckpt model/checkpoints/<version>
```

All three are `t5-small` (60M params, ~242 MB of fp32 weights), same harness
(`model/train.py`), same hyperparameters, CPU only. What differs between them
is **the training data**, and that is the whole point of the sequence.

| version | data | synthesis flag | in-dist prompt-match | OOD prompt-match | gap |
|---|---|---|--:|--:|--:|
| `v1-confounded` | `scene_train.jsonl` | (none) | **90.7%** | **25.0%** | 65.7 pts |
| `v2-deconfounded` | `scene2_train.jsonl` | `--deconfound` | **86.0%** | **62.5%** | 23.5 pts |
| `v3-staged` | `scene3_train.jsonl` | `--deconfound --stage --max-cast 8` | 85.8% (like-for-like) | **70.8%** | 15.0 pts |

## v1-confounded

* **Path**: `model/checkpoints/v1-confounded/` (weights `md5 2c2a5e19...`).
  Original training output directory, left in place: `model/scene_ckpt/`
  (which also holds the trainer's `checkpoint-2250/` optimizer state).
* **Data**: `model/checkpoints/v1-confounded/data/scene_train.jsonl` (6000 rows)
  and `scene_val.jsonl` (700 rows sampled, val prompts filtered disjoint from
  train). Generated by:

  ```bash
  python model/scene_synth.py --n 6000 --val 700 --outdir model/data --prefix scene
  ```

* **Training command** (run from `model/`):

  ```bash
  USE_TF=0 python model/train.py --train model/data/scene_train.jsonl \
    --val model/data/scene_val.jsonl --out model/scene_ckpt \
    --epochs 6 --batch 16 --lr 3e-4 --max-in 104 --max-out 176 --val-cap 200
  ```

* **Run time**: `train_runtime` **530 s** (8 CPU threads, 2250 steps, 6 epochs).
  No GPU. Log: `model/scene_train.log`.
* **Final eval_loss**: 0.9240.
* **Measured rates** (Attempt 22 §4-5, full text in `summary.txt` here and in
  `model/eval_out/`):

  | | in distribution (150 held-out val prompts) | out of distribution (24 hand-written) |
  |---|--:|--:|
  | parse | 100.0% | 100.0% |
  | render (after repair) | 100.0% | 100.0% |
  | valid, zero problems, no repair | 68.7% | 62.5% |
  | byte-identical to reference DSL | 0.0% | 0.0% |
  | cast count | 100.0% | **33.3%** |
  | background | 100.0% | 100.0% |
  | actions | 91.3% | 79.2% |
  | ball interaction | 99.3% | 100.0% |
  | **every stated field at once** | **90.7%** | **25.0%** |

* **Known defect**: the training set made "count the clauses" and "read the
  numeral" the same function in **99.9%** of examples (5681/5688). The model
  learned the clause count and ignores the numeral - 15/15 on the controlled
  probe (`model/eval_out/clause_probe.json`). This is the confound the name
  refers to, and it is why the OOD gap is 65.7 points.

## v2-deconfounded

* **Path**: `model/checkpoints/v2-deconfounded/` (weights `md5 feeff5c9...`).
  Original training output directory, left in place: `model/scene_ckpt2/`.
* **Data**: `model/checkpoints/v2-deconfounded/data/scene2_train.jsonl` /
  `scene2_val.jsonl`. Generated by:

  ```bash
  python model/scene_synth.py --n 6000 --val 700 --outdir model/data \
    --prefix scene2 --deconfound
  ```

  `--deconfound` states the count but describes only a random subset of the
  cast (p=0.45), and rewrites the scene to one shared action described in one
  clause (p=0.22). Clause count still equals cast size in **68.0%** of
  examples, down from 99.9%.

* **Training command**: identical to v1 except `--train`/`--val`/`--out`:

  ```bash
  USE_TF=0 python model/train.py --train model/data/scene2_train.jsonl \
    --val model/data/scene2_val.jsonl --out model/scene_ckpt2 \
    --epochs 6 --batch 16 --lr 3e-4 --max-in 104 --max-out 176 --val-cap 200
  ```

* **Run time**: `train_runtime` **531.7 s** (8 CPU threads, 2250 steps).
  No GPU. Log: `model/scene_train2.log`.
* **Final eval_loss**: 0.9470 - *worse* than v1 on a harder, less predictable
  dataset, which is the point about loss not being the metric here.
* **Measured rates** (Attempt 22 §6; `summary.txt` here, `model/eval_out2/`):

  | | in distribution (150) | out of distribution (24) |
  |---|--:|--:|
  | parse | 100.0% | 100.0% |
  | render (after repair) | 100.0% | 100.0% |
  | valid, zero problems, no repair | **40.0%** | 54.2% |
  | byte-identical to reference DSL | 0.0% | 0.0% |
  | cast count | 100.0% | **83.3%** |
  | background | 100.0% | 100.0% |
  | actions | 88.7% | 87.5% |
  | ball interaction | 97.3% | 95.8% |
  | **every stated field at once** | **86.0%** | **62.5%** |

* **The trade, stated honestly**: 4 points of in-distribution accuracy paid to
  gain 37.5 points out of distribution; generalisation gap 65.7 -> 23.5.
* **Known defects**: `valid` fell 68.7% -> 40.0%, driven by duplicate colours
  (71/150, against 28/150 for v1) - a global constraint an autoregressive
  decoder cannot see, currently carried by `repair()`. Cast size saturates at
  3-4 when asked for six (0/3 on that group). Positions collapse to a handful
  of modal x values (6.9, 8.7, 9.2, 9.6).

## v3-staged

* **Path**: `model/checkpoints/v3-staged/`. Original training output directory,
  left in place: `model/scene_ckpt3/`.
* **Data**: `model/checkpoints/v3-staged/data/scene3_train.jsonl` /
  `scene3_val.jsonl`. Generated by:

  ```bash
  python model/scene_synth.py --n 6000 --val 700 --outdir model/data     --prefix scene3 --deconfound --stage
  ```

  `--stage` samples the cast positions **jointly** (a span at or above the
  target for that cast size, gaps at least a silhouette apart, then shuffled so
  cast order is not x order), clusters 12% of scenes and always says so in the
  prompt, picks walk destinations with clearance, and states a true spatial
  fact in 61.2% of prompts. The cast range is 1-8, not 1-5.

* **Training command**:

  ```bash
  USE_TF=0 python model/train.py --train model/data/scene3_train.jsonl     --val model/data/scene3_val.jsonl --out model/scene_ckpt3     --epochs 6 --batch 16 --lr 3e-4 --max-in 160 --max-out 256 --val-cap 200
  ```

  **`--max-out 256` is not optional and is not a free choice.** v3 targets are
  longer (mean 113.9 tokens, max 252); at v2's `--max-out 176`, 11.28% of
  training targets would be silently truncated mid-scene. Measured over all
  6000 rows, 256 truncates 0.00%.

* **Run time**: `train_runtime` **548.5 s** (8 CPU threads, 2250 steps).
  No GPU. Log: `model/scene_train3.log`.
* **Final eval_loss**: 1.0042 (v2 0.9470, v1 0.9240) - higher again, on a
  higher-entropy target, for the third time in this sequence.
* **Measured rates**, beam4 with the duplicate-colour logits processor, which
  is the configuration this checkpoint should be used in:

  | | in distribution (150) | out of distribution (24) |
  |---|--:|--:|
  | parse | 98.0% | 100.0% |
  | render (after repair) | 98.0% | 100.0% |
  | valid, zero problems, no repair | **80.7%** | **70.8%** |
  | duplicate-colour problems | **0** | **0** |
  | cast count | 100.0% | **95.8%** |
  | background | 100.0% | 100.0% |
  | actions | 85.7% | 83.3% |
  | **every stated field at once** | 85.7% (layout excluded, like-for-like with v2) | **70.8%** |

* **Decoding matters more than the weights for staging.** Under `beam4` this
  checkpoint stages at 0.182; under `do_sample=True, top_p=0.95` it stages at
  **0.875**, with 74.3% of scenes clearing the worse hand-written reference
  clip. Sampling costs 13-20 points of in-distribution obedience and *gains*
  4.2 points out of distribution. Use sampling with `--rerank` for staging,
  beam4 for maximum in-distribution obedience. See ATTEMPTS.md Attempt 23 §6
  and §9.
* **Known defects**: cast size saturates at 6 when asked for nine (the wall
  moved from 6 to 9 with the range extension, it did not disappear); the model
  does **not** obey stated spatial instructions above chance (+2.7 points of
  lift over a mismatched-pair baseline, in distribution); `parse` 98.0% is an
  inference-time length cap on 7-8 character casts, not a format failure -
  raise `--max-out` above 256 for large casts.

## Verification

`model/verify_checkpoints.py` loads every directory under
`model/checkpoints/`, runs the two prompts Attempt 22 published raw strings
for, and writes `model/checkpoints/verify.json`.

```bash
USE_TF=0 python model/verify_checkpoints.py
```

Both preserved checkpoints load. **v2-deconfounded reproduces Attempt 22's
published headline string byte-for-byte** on
*"two friends meet in the park, one waves, then they kick a ball around"*:

```
bg park dur 91 | cast ana blue 96 100 ; bo amber 92 90 |
prop ball 58 100 ; tree 69 110 |
tl 1 26 bo walk 92 ; 8 28 ana wave ; 28 47 bo kick ball ana ; 57 79 bo walk 92
```

zero structural problems, zero repairs - which is what Attempt 22 §8 recorded.
v1-confounded loads and parses; on the same prompt it emits a cast of **one**
with two `kick ball bo` events referring to a character it never declared, the
cast/timeline desync Attempt 22 §5 named. That is the expected v1 behaviour,
so a load that produced anything else would be the alarm.

The weights under `model/checkpoints/` are md5-identical to the originals in
`model/scene_ckpt/` and `model/scene_ckpt2/`; both copies exist deliberately.
